# Тихий список

Небольшой список задач для тестового задания The Digital. Добавление, отметка выполнения, удаление и сохранение после обновления страницы. Написан на HTML, CSS и JavaScript без фреймворка и серверной части.

**[Открыть сайт](https://slavques.github.io/the-digital-todo/)**

## Возможности

- Добавление кнопкой или Enter, проверка пустого ввода и ограничение в 300 символов.
- Выполнение и возврат задачи в работу, удаление, фильтры и прогресс.
- Пагинация по 6 задач, плавное изменение высоты списка и зачеркивание в обе стороны.
- Отмена последнего удаления с восстановлением статуса и позиции задачи.
- Светлая и тёмная темы. Выбор сохраняется независимо от списка задач.
- Сохранение задач и статусов в localStorage, синхронизация вкладок одного браузера.
- Работа в памяти с явным предупреждением, если хранилище недоступно.
- Адаптивный интерфейс, клавиатурное управление, сохранение фокуса и объявления об изменениях для вспомогательных технологий.

При первом открытии список пуст. Данные не отправляются на сервер и не синхронизируются между устройствами. Очистка данных браузера удаляет список. При одновременном редактировании в разных вкладках применяется последнее сохранение.

При первом входе тема выбирается по настройке устройства. Кнопки с солнцем и луной переключают светлую и тёмную темы. Отмена удаления доступна до следующего добавления, изменения статуса, удаления, внешнего обновления задач или перезагрузки страницы.

## Локальный запуск

Для разработки рекомендуется **Node.js 24 LTS**, минимум — 22.12. GSAP поставляется вместе со статическими файлами; Node нужен для локальных команд и проверок.

```sh
npm ci
npm start
```

Открыть [http://127.0.0.1:4173](http://127.0.0.1:4173). Python и сборка для запуска не нужны. HTML следует открывать через HTTP: браузер загружает JavaScript как ES-модуль.

## Проверки

```sh
npm run format:check
npm test
npx playwright install chromium webkit
npm run test:e2e
```

На Linux для браузеров могут понадобиться системные библиотеки: `npx playwright install --with-deps chromium webkit`.

Модульные тесты проверяют неизменяемые операции со списком, границы ввода и проверку сохранённых данных. Браузерные сценарии автоматически поднимают локальный сервер и проверяют CRUD, сохранение после обновления, фильтры, фокус, безопасный вывод текста, повреждённое и недоступное хранилище, восстановление записи, синхронизацию вкладок и узкие экраны. Есть автоматическая проверка axe для части требований доступности. Браузерные сценарии предусмотрены для Chromium и мобильного WebKit. Проверяются обе темы, системная настройка, сохранение выбора и отмена удаления; эмуляция не заменяет проверку на физическом телефоне.

Проверки запускаются локально. Автоматический workflow GitHub Actions отключён; публикация выполняется через статическую ветку gh-pages. Отчёт локального Playwright: `npx playwright show-report`.

## Структура

- `index.html`, `styles.css`, `tokens.css`, `base.css` — разметка, компоненты и общая система оформления.
- `theme.js` — ранняя инициализация темы, переключение и сохранение выбора.
- `model.js` — чистая логика и проверка данных.
- `app.js` — события, рендер, фокус и хранилище.
- `assets/` — иконка и локальные шрифты Onest с лицензией SIL OFL.
- `tests/` — модульные и браузерные тесты.
- `scripts/` — локальный HTTP-сервер и подготовка статического сайта.

Текст задач выводится через textContent. Недоверенные записи из хранилища проверяются; некорректные элементы и повторные ID отбрасываются. Изменения не зависят от сторонних сетевых сервисов. Шрифты загружаются с того же сайта.

## AI-инструменты и решения

Использован **OpenAI Codex**: анализ требований, реализация, тесты, проверка интерфейса и независимое ревью изменений. Дизайн рабочего интерфейса переработан с [Hallmark](https://github.com/nutlope/hallmark) в app-режиме. [Impeccable](https://github.com/pbakaus/impeccable) использован для Operate-аудита, а [Taste Skill](https://github.com/Leonxlnx/taste-skill) — для критики типографики, геометрии контролов и состояний. Его маркетинговая композиция с hero и экранными секциями к этому инструменту не применялась. Одна локальная шрифтовая семья Onest, компактная рабочая область и сдержанный акцент; обе темы проверяются отдельно.

Процесс: проверяемые требования → небольшие изменения → автоматические проверки → работающий браузер и скриншоты → независимое ревью → исправления. Подход согласуется с [актуальными рекомендациями Claude Code](https://code.claude.com/docs/en/best-practices), но не требует использования Claude Code или добавления сложной инфраструктуры.

Простой стек выбран по объёму задания: четыре основные функции не требуют backend, авторизации или фреймворка. Кроме локально поставляемого GSAP используются только инструменты тестирования и форматирования.

## Публикация

```sh
npm run build
```

Папка site/ содержит публичные файлы для статического хостинга. Сайт публикуется из корня ветки gh-pages стандартным механизмом GitHub Pages, без пользовательской CI-цепочки.

## Движение

GSAP поставляется локально в assets/vendor с исходным copyright-заголовком. Упругие появления задач, отклик кнопок, движение индикатора фильтров и всплывающие уведомления работают без CDN. Анимации отключаются при prefers-reduced-motion. Подсветка строк следует движению мыши и клавиатурному фокусу, без залипания после удаления.
